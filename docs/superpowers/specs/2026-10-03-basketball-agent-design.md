# 最强经纪人：首版设计

日期：2026-10-03。状态：用户已审核同意；尚未开始产品代码实现。游戏正式名称：最强经纪人。

## 目标与已确认玩法

面向手机操作的本地网页小游戏，未来考虑虎扑 AI Game／AI 工坊接入。核心循环：访问球队 → 查看当地报价 → 买入或卖出 → 前往另一队 → 赚取差价。

- 使用真实 NBA 球队及真实阵容作为开局配置，全队球员均可购买。
- 初始资金 15,000,000 美元；仓库最多 5 名球员。
- 球员基础价格为所选赛季的当赛季年薪，不采用剩余合同总额。
- 移动到另一队消耗一天；30 天结算现金与持仓价值。
- 只显示当前球队报价。其他球队仅保留访问时的历史报价和日期，不显示当前价格或涨跌预测。
- 提供真实新闻摘要、比赛数据、发生日期及来源，不提供买卖建议。玩家据此判断其他球队的潜在价格变化。
- 买入后从球队转入仓库；卖出后转入目标球队。同一球员在整局内只有一个归属。

## 建议采用的首版细则（本次审核范围）

采用固定的真实历史数据快照，离线运行。每个游戏日对应一个明确的真实日期；不把游戏推进当作实时新闻更新。相比实时接口，这种方式便于复现交易、核查数据，也无需后台服务。纯随机价格无法体现真实信息判断，因此不作为主方案。

数据准备时选择可核验且包含连续 30 天比赛和新闻的最近完整区间，锁定对应赛季、开局阵容及年薪。页面显著显示赛季、数据区间和采集截止日期。该区间尚未选定，选定后需提供数据覆盖说明；禁止用虚构新闻或薪资补缺并声称完整。

开局为第 1 天，默认从湖人队开始，可在开局前改选球队。到第 30 天仍可买卖，但不能再移动；点击结算结束本局。买卖不耗天数，无手续费、旅行费和额外随机事件。移动不能选择当前球队。

报价上限和下限为基础年薪的 130% 和 70%（建议参数，可调整）。每队对球员有不同报价：依据位置需求产生固定偏好，再叠加截至当日已发生的真实新闻与比赛表现影响。每天一次更新，买卖和刷新页面不触发价格重抽；同一球队同一球员当天买入价和卖出价一致，避免同地即时套利。

首版使用可复现的简单计分模型：位置偏好最多 ±8%；比赛与新闻累计影响最多 ±22%；最终乘数限制在 0.70–1.30。比赛以历史区间开始前的数据建立球员基准，之后用近期相对表现分档。新闻仅对有明确证据的伤病、复出、交易或角色变化编码；缺少依据时影响为零。具体计分映射在数据整理时形成配置及说明，不向玩家显示其他球队预测，不读取未来信息。

游戏内交易只改变虚拟归属，不改写真实新闻和真实比赛记录；球队偏好依据开局阵容固定。所有交易为游戏抽象，不模拟 NBA 薪资匹配或真实转会审批。

结算持仓采用当日统一参考价值（年薪乘以比赛／新闻影响，不含球队偏好），避免为最后所在地提供特殊清仓优势。总资产 = 现金 + 持仓参考价值；总收益 = 总资产 − 1500 万；同时分开显示已实现盈亏与持仓浮动盈亏。玩家目标是在 30 天内尽量提高总资产，无强制收益门槛。

## 界面与技术结构

使用 HTML、CSS、JavaScript 模块，静态资源和本地 JSON 数据，不引入后台、账户系统或平台 SDK。通过本地 HTTP 服务试玩，未来可打包静态部署。

手机页面顶部固定显示天数、当前球队、现金和仓库数量；提供球队市场、仓库、球队地图、新闻四个入口。市场支持姓名／位置过滤，展示年薪基准、当地报价和买入按钮。仓库显示成本、当地卖价与可实现盈亏。地图只展示历史报价及访问日期。新闻按当天及过去日期展示，不泄露未来记录。

拆分数据层、纯交易／日历／定价逻辑、界面层与存档层。金额用整数美元；球员和球队用稳定 ID。每次成功交易或移动后保存本地存档，含数据版本；读到损坏或不兼容存档时提示重开，不静默覆盖原存档。

## 边界与验证

资金不足、仓库满员、球员不属于当前球队、无持仓却卖出、重复点击和结束后操作均不得改变状态。按钮禁用与逻辑校验同时执行。卖出按独立球员的实际成本计算，买回建立新成本。

自动验证覆盖资金守恒、唯一归属、五人容量、移动耗日、30 天边界、报价上下限、无未来信息和结算公式；以固定数据完成买入 → 移动 → 卖出 → 结算的完整回归。页面检查手机尺寸布局和主要操作；不使用 Computer Use。

数据检查包括全联盟球队及阵容覆盖、重复球员、薪资币种／赛季、日期范围、来源链接和新闻影响证据。缺失或有争议的合同字段明确列出，处理后才可宣称真实数据完整。

## 排除与待验证

首版不含广告、支付、联网排行榜、自动实时抓取、照片／队徽素材、动画视频或后台服务。真实球队与球员先以文本呈现。

虎扑接入格式、SDK、审核、广告分成和公开上线所需素材授权等，待正式资料确认。本地原型完成不代表平台适配或可发布。
