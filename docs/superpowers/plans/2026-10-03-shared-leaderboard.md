# M4 真实成绩保存实施计划

> 在当前对话使用 superpowers:executing-plans 逐项实施。依据：docs/leaderboard-design.md，用户最后回复“界面可以，就这样”。

目标：起名必填、进行中资产更新、结算保留在所选难度榜；刷新及另一浏览器均能读取共享成绩。

架构：复用已试玩行情公式，提取浏览器与服务端共用规则模块。浏览器保存局标识、操作流水与待同步队列；服务端重放流水计算资产，用每局密钥校验写入、前缀检查禁止改写历史、版本条件更新防止并发覆盖。排行榜以局为记录，进行中与已结算标记清晰；同资产按创建时间及局ID稳定排序。多局均保留，不用昵称作身份或覆盖别人。

技术：原生 JavaScript ES modules、Fetch API、SQLite；云适配使用托管SQL接口，具体托管待用户选择。页面继续GitHub Pages。

约束：三难度本金3000万/1000万/500万美元、容量15、30天、移动耗1天；默认ATL、英文队名排序；报价规则不新增资料估值模型；数据库只读快照不改；不使用Computer Use；Markdown UTF-8无BOM。正式排名隔离规则与名单版本。

关注：重复提交不能重复入榜；断网不能丢结算；旧请求不能覆盖新资产；必填昵称与恶意HTML；刷新恢复不能切换难度或报价。
